# Cinematic Interactions — Fabric 1.21.1

Отдельный порт текущей NeoForge 1.21.1 **0.18.12** на Fabric для Minecraft **1.21.1**; версия порта — **0.18.18**
(0.18.12 + исправления ниже). Общий старый проект
`../` (цель 1.21.1 там осталась на 0.12.x) этой работой не менялся и не используется; его JAR сохранены.

Порт берёт исходники NeoForge почти без изменений: Minecraft-код один и тот же (1.21.1, имена Mojang с параметрами
Parchment 2024.11.17 — как в NeoForge-проекте). Заменена только прослойка загрузчика: события NeoForge — колбэки
Fabric API и миксины в тех же местах игры, сеть, файл настроек, обёртки моделей, регистрация клиента.

Есть всё, что есть в NeoForge 0.18.12: все сцены станций (верстак со справочником и раскладкой, три печи, стол
зачарований, наковальня, точило, кузнечный стол, камнерез, ткацкий станок, стол картографа, варочная стойка,
сборщик, костры, кафедра, маяк, проигрыватель, резная полка), плавные входы и выходы, переходы к соседней станции,
быстрый повторный вход, обзор от третьего лица, руки со скином, предметы на блоках для всех игроков, позы других
игроков, редакторы всех станций, три профиля каждой станции, режим разработчика, пробный клиентский режим,
Shift+клик в станцию, полевой справочник JEI (с JER и JEP), эффекты инвентаря (Inventory Particles / Interactions),
совместимость с Punchy и предварительный API аддонов. Раскладки и тексты общие с NeoForge.

## Установка

- Minecraft **1.21.1**, Java **21**, Fabric Loader **0.16.14+**, Fabric API **0.116.17+1.21.1** или новее.
  Сам мод работает с Loader 0.16.14, но проверенные дополнения требуют новее: Punchy и Moonlight (Amendments) —
  0.18+, Inventory Particles / Interactions — 0.19.3+. Тесты с ними шли на 0.19.5.
- Готовый файл: `../../release/fabric/1.21.1/Cinematic Interaction-Fabric-1.21.1-0.18.14.jar` (прежние 0.18.12 и 0.18.13 там же);
  0.18.15–0.18.18 пока только в `build/libs/`. 0.18.16 меняет формат сети (`protocol_12`): клиент и сервер должны быть 0.18.16.
  В папке `mods` должна быть только одна сборка Cinematic Interactions (не вместе со старой 0.12.2 для 1.21.1).
- Для полного режима тот же JAR и Fabric API ставятся и на сервер. Без мода на сервере работает пробный
  клиентский режим (включается в «Сетевая игра», только из главного меню; см. `../../docs/client-only-preview.md`).
- Необязательно: **Mod Menu** (кнопка настроек в списке модов). Экран настроек с поиском и вкладками встроен в мод,
  Cloth Config не нужен. Без Mod Menu настройки меняются в `config/cinematic-client.json`.
- Профили раскладок можно скопировать из NeoForge: `config/cinematic-table-layouts.json`,
  `cinematic-furnace-layouts.json`, `cinematic-surface-layouts.json`, `cinematic-spatial-layouts.json` —
  формат тот же. Настройки NeoForge (`cinematic-client.toml`) автоматически не переносятся.

## Чем отличается от NeoForge

- **Настройки** — `config/cinematic-client.json` (те же ключи, что в TOML NeoForge). Экран открывает Mod Menu;
  у него вкладки «Общие», «Станции», «Камера» и «Дополнительно» (там же все 18 профилей в режиме разработчика).
- **Сеть.** NeoForge согласует одну версию для всех каналов («11»). Fabric согласует каждый канал отдельно, поэтому
  порт регистрирует пустой канал `cinematic:protocol_11`: сторона без него (или старая 0.12.x с теми же именами
  каналов) считается сервером/клиентом без мода. Формат самих пакетов не менялся.
- **HUD в сцене.** Скрываются те же ванильные слои (остаются чат, субтитры, F3, индикатор сохранения, список
  игроков). Свои элементы HUD других модов на Fabric рисуются через общий колбэк, их сцена не прячет.
- **Топливо печи.** NeoForge спрашивает время горения у предмета для конкретной печи; на Fabric — ванильная таблица
  топлива (`AbstractFurnaceBlockEntity.isFuel`, в неё входят и топлива Fabric `FuelRegistry`).
- **События NeoForge**, которых нет у Fabric и которые моды могли бы слушать, не вызываются: «предмет создан»
  (крафт на верстаке сцены) и «предмет выплавлен» (забор из печи). Ванильные триггеры, опыт и рецепты — как в окне.
- **JEI** подключается через точку входа `jei_mod_plugin` (на NeoForge — аннотация). Проверены JEI 19.43 и JEP 4.0.5
  для Fabric. JER 1.6.0.17 для Fabric сам не загружается в JEI (в его JAR нет `jeresources.api`).
- **Penchant Reforged и Apotheosis** проверялись только в NeoForge (Apotheosis для Fabric не выпускается); код,
  уступающий окно незнакомому меню стола, перенесён без изменений, но в Fabric с этими модами не запускался.
- **0.18.13:** быстрый выход из сцены и сразу E (инвентарь) больше не переводит станцию на обычное окно до
  перезахода; инвентарь открывается поверх отхода. Причина и проверки — TESTING.md. В NeoForge 0.18.12 тот же код.
- **0.18.14:** в списке серверов — строка с состоянием клиентского режима (открывает его настройку) и один раз, пока
  режим выключен, короткое окно «Cinematic Interactions · Игра на сервере» с кнопками «Включить клиентский режим» /
  «Продолжить». Только в этом порте; подробности — TESTING.md.
- **0.18.15:** пиксельные круги стола зачарований проявляются прозрачностью (без чёрной стадии), яркий градиент,
  стоимость предложений всегда перед линиями круга (лёгкая тень, без подложки). Только в этом порте; подробности — TESTING.md.
- **0.18.16:** использование станции в прыжке начинается после приземления (или открывается окно блока); вещи со
  столешницы переезжают в сетку обычного окна верстака; «Разложить» сначала убирает лишнее с клеток; выбор между
  конфликтующими рецептами Polymorph в сценах верстака, печей и кузнечного стола. Подробности — TESTING.md.
- **0.18.17:** клавиша в подсказках — латинской буквой назначенной клавиши (при русской раскладке H не «Р»); тело
  работающего игрока поворачивается к станции (руки от третьего лица); у костра закрыты колени, поднятая нога согнута;
  формы камнереза уходят от соседних блоков. Подробности — TESTING.md.
- **0.18.18:** прозрачность на верстаке не мерцает и стопки не вдавливаются друг в друга; шкалы костра стоят на еде и
  закрываются рукой; круги стола зачарования не мерцают с шейдерами; стекло маяка не прячет предметы за собой, иконки
  сил закрываются рукой и блоками. Подробности — TESTING.md.
- Найденные при переносе ошибки исправлены здесь (в NeoForge не трогались): уборка позы кафедры на `RETURN`
  вместо `TAIL` (в собранной игре кафедра без книги под сохранённой раскладкой роняла кадр «Pose stack not empty»),
  наковальня проверяет цену слотом результата меню (`mayPickup`, как с Easy Anvils), Shift+клик стопки на маяк
  кладёт один предмет, как в NeoForge (там это патч `BeaconMenu`; в ванильном окне Fabric — нет), тест клиентского режима
  вызывает клавишу использования через invoker-миксин, а не reflection по имени Mojang.

## Сборка

```powershell
$env:JAVA_HOME = 'C:\Users\evgen\AppData\Local\Programs\Eclipse Adoptium\jdk-21.0.12.8-hotspot'
.\gradlew.bat --offline build
```

JDK 21, Gradle 9.6.0 (wrapper), Fabric Loom 1.16.3, Loader 0.16.14, Fabric API 0.116.17+1.21.1. Все зависимости
уже в кэше Gradle; `--offline` гарантирует, что ничего не скачивается. Результат: `build/libs/`.
`-PjeiFabric` компилирует адаптер JEI против Fabric-сборки из `test-mods/jei` (по умолчанию — против API из
NeoForge-JAR JEI 19.57 в кэше, API одинаковый). `compileExampleAddonJava` проверяет пример аддона из `../../examples`.

## Проверка

- `bash tools/showcase.sh` — Showcase (тот же сценарий и имена кадров, что в NeoForge) в dev-клиенте;
  `FROM=k ONLY=true`, `SETTINGS=false`, `MODS=<папка test-mods>`.
- `bash tools/prod_showcase.sh` — тот же сценарий в **настоящем** клиенте Fabric с собранным JAR (установка Fabric
  из Modrinth app: `tools/prod_client.py`). `LOADER=0.19.5`, `EXTRA="test-mods/iris/*.jar"`, `SETTINGS=false`.
- `tools/prod_server.py` — настоящий выделенный сервер Fabric или ванильный (из кэша Loom и Modrinth), RCON.
- `tools/compare_frames.py` — кадры NeoForge и Fabric попарно.
- Перед каждым автоматическим запуском `soundCategory_master:0.0`. Dev- и prod-клиенты используют разные папки
  `run/*`; не пересобирайте проект, пока работает dev-клиент.

Результаты — [TESTING.md](TESTING.md). Тестовые моды лежат в `test-mods/` (локальные копии, в JAR не входят).
