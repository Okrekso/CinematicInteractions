# Fabric 1.21.10 и 1.21.11 — заметки для продолжения

Порты 0.12.3 сделаны 12 октября 2026 года. Основа — существующий рабочий порт 1.21.9 (0.12.2),
визуальный эталон — NeoForge 1.21.1. Старые исходники слоёв 1.21–1.21.9 и выпущенные JAR не заменялись.

## Что сохраняется

Все станции, позы, точки предметов, длительности движений, easing, анимации рук и эффекты взяты из текущего
проекта. `Scene`, `CameraRig`, `Hands`, `Reach`, переходы и справочник рецептов сохраняют существующее поведение.
Текстуры, модель молотка, переводы и иконка берутся прямо из ресурсов NeoForge. Сундуки и бочки остаются с GUI.
Исправления интерполяции камеры и удержания наведения у костра из 0.12.2 сохранены.

## Где адаптация

| Версия / файл | Причина |
|---|---|
| 1.21.10 `SceneRenderer`, `IrisCompatibility` | Теневые очереди Iris не должны забирать основной кадр сцены; привязки программ свечения и прозрачных предметов копируются с соответствующих ванильных pipeline |
| 1.21.11 `CameraMixin` | `setup` принимает Level; новые геттеры и read-only векторы; roll и интерполяция прежние |
| 1.21.11 `Fx`, `ItemPlacer`, access widener | RenderSetup вместо CompositeState; перенос текстур, sampler, света, overlay и output target прозрачного предмета |
| 1.21.11 `VertexConsumerWrapper` | Новый setLineWidth и packed setColor с сохранением множителя прозрачности |
| 1.21.11 `ScreenMixin`, `ItemInHandLayerMixin` | Новые сигнатуры init и submitArmWithItem; запуск Showcase и скрытие настоящего предмета за молотком |
| 1.21.11 `LoomStation` | Потребитель буфера запрашивается перед каждым слоем ткани; смена RenderType заканчивает предыдущий общий буфер |
| `build.gradle` sourcePatches | Identifier / RenderTypes / PlayerModel / GameRules, Camera API, SavedDataType, sampler страниц, контур соседней станции и команды тестового мира |

`RenderOutputMixin` с 1.21.6 уже не регистрируется: страницы работают через GPU attachments. На 1.21.11
этот неиспользуемый старый класс исключён из сгенерированных исходников, поскольку его target удалён из игры.

## Особенность Iris

Одной регистрации `EMISSIVE_ENTITIES` недостаточно: в Iris 1.9.7 и 1.10.8 подбор по формату мог выбирать
программу частиц `SPS`, из-за чего исчезали текстуры магических кругов. `IrisPipelines.copyPipeline` копирует
привязку программы `EYES` к нашему GLOW, а `ENTITY_TRANSLUCENT` — к FADING_ITEM. Геометрия и ADDITIVE blend
остаются нашими. Вызов внутреннего API отражением изолирован в `IrisCompatibility`; если метод исчезнет,
пишется предупреждение и используется публичный API. Новую версию Iris обязательно проверять по кадрам.

## Как проверять дальше

См. [TESTING.md](../TESTING.md) и [README.md](../README.md). Источник истины API — именованные исходники
конкретной версии из Loom `genSources`, а не названия из 1.21.1. Не редактировать `build/<версия>/generated/java`.

Автопроверки состояния не обнаруживают исчезнувшую геометрию: обязательно открыть кадры верстака,
зачарования, ковки, ткани, карты, варки, кафедры, маяка, переходов и вида со стороны. Для плавности использовать
`FrameProbe`, исключающий снимки экрана. Скины и фаза анимации между отдельными прогонами могут отличаться.

Контактные листы сравнения лежат в `build/port-verification/`; исходные кадры —
`run/<версия>/showcase/screenshots/` и `run/<версия>/showcase-iris/screenshots/`.
