# Punchy! — совместимость рендера рук

Проверяемые сборки: NeoForge 1.21.1 — **0.18.1**, Fabric 1.21.11 — **0.12.4**,
Fabric 26.3 — **0.18.1**. Старые выпущенные JAR сохраняются отдельно.

## NeoForge 1.21.1

Исправление Cinematic Interactions **0.18.1**. Проверяемая версия:
[Punchy 2.8f для NeoForge 1.21.1](https://modrinth.com/mod/punchy-fpa/version/vNMBHZKV).
Punchy установлен в отдельные игровые клиенты проекта `run-showcase` и `run-showcase-iris`;
пользовательская сборка Modrinth и сервер Skuf не изменялись.

## Причина и поведение

Punchy добавляет собственную отрисовку в начало `ItemInHandRenderer.renderHandsWithItems`.
NeoForge вызывает `RenderHandEvent` позже, отдельно для каждой руки. Поэтому прежняя отмена события
не убирала уже нарисованные руку и предмет Punchy: они оставались поверх рабочих рук сцены.
Баг воспроизведён с настройками Punchy по умолчанию: блок досок закрывал правую часть верстака.

`FirstPersonHandsMixin` теперь оборачивает весь проход рук через MixinExtras `WrapMethod`.
Во всех фазах сцены INTRO / ACTIVE / OUTRO обычный проход не вызывается, вместе с ранними
инъекциями Punchy. Вне сцены original вызывается с исходными аргументами: анимации и предметы
Punchy снова отображаются. Руки сцены и модели других игроков не скрываются.

Простая cancellable HEAD-инъекция оказалась недостаточно надёжной: в экспортированном классе
Punchy вызывался до неё. У окончательной обёртки проверен преобразованный код запущенной игры,
в том числе с Iris: ранний рендер Punchy находится внутри original.

Дополнительный клиентский `@Pseudo`-mixin для `CameraAnimationState.isActive` отключает влияние
сохранённого смещения камеры Punchy только пока работает сцена. Само состояние и настройки
Punchy не перезаписываются. Обязательной зависимости от Punchy нет.
Форматы пакетов и версия сети **8** не менялись.

## Проверки

Клиенты: Minecraft 1.21.1, NeoForge 21.1.255, Java 21.
Шейдерный клиент: Iris 1.8.14-beta.1, Sodium 0.8.13, Complementary Reimagined r5.9.3.
Каждый запуск создаёт отдельный мир через `-PshowcaseWorld=...`, прежние миры сохраняются.

Дата проверки: 15–16 октября 2026.

| Запуск | Проверено | Пройдено | Ошибок проверок |
|---|---|---:|---:|
| С Punchy, обычный, акт 0 | Верстак, редактор, рецепты, крафт, предметы, вход и выход | 75 | 0 |
| С Punchy + Iris, от t до конца | Соседние станции, раскладка рецептов, обзор от третьего лица, проигрыватель, быстрый возврат, наблюдатели | 61 | 0 |
| С Punchy + Iris, от f, только акт | Оба костра, сидение, редакторы, таймеры, затухание подсказки и выход | 68 | 0 |
| Без Punchy, акт a | Запуск без стороннего класса, редактор наковальни, ковка, чары, переименование, выход | 31 | 0 |

Итого **235 успешных проверок**, 0 ошибок проверок в финальных четырёх запусках.
Просмотрены кадры входа, работы, переноса предметов, выхода, возвращения обычной руки,
свободного обзора и сидения у огня, в том числе с шейдерами.
`gradlew build` завершился успешно. В JAR есть оба новых клиентских mixin, версия 0.18.1;
JAR Punchy, сторонние классы и декомпилированные файлы в выпуск не включены.

Это целевые проверки конфликта рендера, а не новый полный прогон всех станций.
Другие версии Punchy, пользовательские анимационные ресурспаки и другие моды анимаций
этой проверкой не подтверждаются. Серверная логика и форматы пакетов не менялись.

Журналы, исходное воспроизведение и экспортированные классы находятся в `build/compat-punchy`.
Сторонний JAR и его декомпиляция используются только для локальной проверки и в выпуск мода не входят.
Первоначальная проверка выше относится к **NeoForge 1.21.1 / Punchy 2.8f**.

## Fabric 1.21.11 и 26.3

Дата: 16 октября 2026. Punchy подключён только к отдельным клиентам Showcase.
Пользовательская сборка и сервер не изменялись.

- 1.21.11: [Punchy 2.8f](https://modrinth.com/mod/punchy-fpa/version/eJb6UKkD),
  Fabric API 0.141.6+1.21.11, Java 21. Punchy требует Loader 0.18.0+; проверка — на Loader 0.19.5.
- 26.3: [Punchy 2.8f hotfix](https://modrinth.com/mod/punchy-fpa/version/ZTKLyIXH),
  Fabric API 0.163.0+26.3, Loader 0.19.5, Java 25.
- Iris: 1.10.8 / Sodium 0.8.14 для 1.21.11 и 1.11.7 / Sodium 0.9.3-alpha.1 для 26.3,
  Complementary Reimagined r5.9.3.

На 26.3 исходный дефект воспроизведён: блок в руке Punchy перекрывал верстак. Экспортированный
`FirstPersonHandsAndItemsRenderer` подтвердил, что обработчик Punchy идёт раньше прежней отмены HEAD.
После `WrapMethod` обработчик находится внутри original, который сцена пропускает целиком.
Кадры после исправления показывают только рабочие руки; после выхода блок снова виден в обычной руке.

На 1.21.11 в обычном клиенте исходная лишняя рука не воспроизвелась: прежний HEAD стоял раньше Punchy.
С Iris порядок поменялся: Punchy оказался до проверки Cinematic, что подтверждено дампом класса.
В просмотренных кадрах наковальни с Iris лишняя рука также не проявилась; визуальный дефект для этой версии
не заявляется как воспроизведённый. Версия 0.12.4 получает ту же обёртку всего прохода и защиту камеры,
чтобы сцена не зависела от порядка ранних обработчиков. Это целевое исправление совместимости;
редакторы NeoForge в старый порт не добавлялись.

В 1.21.11 меняется только версия слоя `FirstPersonHandsMixin` с `SubmitNodeCollector`;
в 26.3 обёрнут `submitHandsWithItems` с двумя render state. Обязательной зависимости от Punchy нет,
пакеты и игровая логика не меняются. Флаг `-PwithPunchy` подключает закреплённый тестовый JAR,
а `-PtraceMixins` экспортирует фактический преобразованный класс для проверки порядка вызовов.

Проверены вход/выход, работа с предметами, прозрачность, переходы к соседним станциям, быстрый возврат,

Проверка других версий Punchy и произвольных анимационных ресурспаков не заявляется.

## Fabric 26.2

Полный порт 0.18.1 сохраняет эту защиту рук и камеры, все редакторы и остальные функции текущей сборки.
В 26.2 целиком обёрнут `ItemInHandRenderer.submitHandsWithItems(float, PoseStack, SubmitNodeCollector,
LocalPlayer, int)`. Экспортированные классы обычного клиента и Iris подтверждают, что ранние обработчики
Punchy находятся внутри пропускаемого `original`. Вне сцены вызывается исходный проход; настройки Punchy
не меняются. Подключение Punchy остаётся необязательным.

Проверка выполнена с [Punchy 2.8f для 26.2](https://modrinth.com/mod/punchy-fpa/version/O6KuUYUk),
Iris 1.11.4 / Sodium 0.9.2 и Complementary Reimagined r5.9.3.
Подробные результаты и ограничения — в [отчёте Fabric 26.2](../multiversion/docs/26.2/TESTING.md).
