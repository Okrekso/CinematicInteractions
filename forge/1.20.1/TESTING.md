# Проверки порта Forge 1.20.1

Порт Cinematic Interactions 0.18.11 (основа — исходники NeoForge 1.21.1 0.18.11) на Minecraft 1.20.1 / Forge 47.
Проверки — 19–20 октября 2026. Все автоматические клиенты запускались с `soundCategory_master:0.0`. Журналы —
`run-*/showcase.log`, `build/acts/*.log` (отдельные акты), `build/net/*.out` (сетевые тесты).

Число проверок считается по строкам `check passed` / `check FAILED` без повторов из итогового отчёта Showcase.

## Сборка

- `./gradlew build` (JDK 21 для Gradle, toolchain Java 17): без ошибок, только предупреждения об устаревших API.
- JAR переобфусцирован в SRG; в нём `cinematic.refmap.json`, `MixinConfigs: cinematic.mixins.json` в манифесте и
  `"refmap"` в конфиге миксинов. Shadow-поля миксинов переименованы (`f_90559_` и т. п.). Access transformer — SRG-имена.

На серверах без мода в журнале сервера нет ни одного упоминания мода. Журнал выделенного сервера — без ошибок.

**Повторный вход после перезапуска сервера иногда зависает** (открытый вопрос). Сервер шлёт всё согласование Forge
(`S2CModData` … `Config forge-server.toml`), клиент не получает ни байта и через 30 с закрывает соединение
(`ReadTimeoutHandler`); у клиента нет ошибок, поток отрисовки свободен, код мода на стеке не встречается. Первый
вход на тот же сервер проходит всегда (7 из 7), второй — 3 из 7, одинаково у dev-клиента и собранного JAR.
Когда вход проходит, верстак возвращается из сохранения. Снять дамп потоков в момент зависания не удалось — в
прогоне с дампом всё прошло. Возможная причина — окружение (петля 127.0.0.1, порт сразу после остановки сервера),
но связь с модом не исключена: нужен отдельный разбор.

## Найдено и исправлено в ходе проверок

- **Собранный JAR не загружался** (каждый миксин падал в настоящем клиенте): MDG Legacy кладёт refmap в JAR, но не
  прописывает его в `cinematic.mixins.json`. Добавлено `"refmap"`. В dev-запусках ошибки не видно.
- **Вылет «Pose stack not empty»** после того, как книгу забрали с кафедры при сохранённой раскладке кафедры:
  в настоящем байткоде `LecternRenderer.render` есть ранний `return` (без книги), `@At("TAIL")` его не ловил.
  Теперь `@At("RETURN")`. В dev-запусках класс перекомпилирован с одним `return` — ошибки не видно.
  **В NeoForge 0.18.11 тот же `TAIL`** — не проверялось, предложено отдельной задачей.
- **Наковальня с Easy Anvils** не ковала при цене 0 (бесплатное переименование): решение теперь за слотом
  результата меню. В NeoForge 0.18.11 — та же формула.
- **Настройки могли откатиться** при быстрых записях (гонка автосохранения и наблюдателя файла Forge) — `Settings.set`.
- Тестовая обвязка: dev-клиент загружал оставленный собранный JAR из того же каталога (`mods/`) рядом со своими
  классами — теперь каталог очищается; зависший клиент останавливается вместе с деревом процессов. Подготовка полки (`setItem` в 1.20.1 не принимает пустой стек), запуск настоящего клиента
  (библиотеки установщика с `include_in_classpath: false`), сервер без мода (`--mixin.config` не передаётся).

## Не проверено

- Два живых игрока одновременно (как и в NeoForge).
- Penchant Reforged: версии для Forge 1.20.1 нет среди одобренных загрузок; поведение с чужими меню проверено актом `fm`.
- Собранный JAR на выделенном сервере отдельной установки Forge (установщик сервера не скачивался; выделенный
  сервер проверен в среде Forge 47.4.10, клиентская часть сервером не загружается — `Dist.CLIENT`).
