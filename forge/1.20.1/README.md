# Cinematic Interactions — Forge 1.20.1

**Текущая бета:** версия `0.18.28` доступна в [GitHub Releases](https://github.com/dcvke/CinematicInteractions/releases); исходники собираются в `build/libs/`.
В неё перенесены новые сцены и исправления актуальной ветки, а также необязательная совместимость с
Polymorph 0.49.11 для верстака, печей и кузнечного стола. Результаты и границы проверки перечислены в
[TESTING.md](TESTING.md). Следующее описание `0.18.11` сохранено как история ранее опубликованного порта.

Отдельный порт Cinematic Interactions на Minecraft **1.20.1** и **Forge 47** (Java 17). Основа — исходники
NeoForge 1.21.1 версии **0.18.11** (хэши исходников на момент переноса — `base-src-0.18.11.sha256`; после сборки
JAR 0.18.11 исходники корня не менялись). Проект NeoForge, Fabric-порты и их JAR этой работой не меняются.
`modid` — `cinematic`, пакет Java — `dev.dyslexic.cinematic`, автор — Southware.

Результаты проверок — [TESTING.md](TESTING.md).

## Установка

Готовый файл: `release/forge/1.20.1/Cinematic Interaction-Forge-1.20.1-0.18.11.jar` (SHA-256 рядом; сборка
кладёт его в `build/libs/`). Нужны Minecraft **1.20.1**, Forge **47.1 или новее** (собрано против рекомендованной
**47.4.10**; полный автотест собранного JAR пройден на Forge 47.3.12, 47.4.0, 47.4.20 и на NeoForge 47.1.106 —
ранней NeoForge для 1.20.1, которая тоже называет себя `forge`), Java **17**.

- **Полный режим** — один и тот же JAR в `mods` клиента и сервера: сцены, общие предметы на блоках, позы и
  эффекты для других игроков, сервер — источник истины для предметов, крафта, зачарования и действий.
- **Сервер без мода** (ванильный или Forge без Cinematic): канал мода необязателен для обеих сторон
  (`NetworkRegistry.acceptMissingOr`, `displayTest="IGNORE_ALL_VERSION"`), клиент входит и ничего своего серверу
  не шлёт. По умолчанию открываются обычные окна. Пробный **клиентский режим** (вкладка «Сетевая игра»,
  меняется только из главного меню) показывает локальные сцены поверх обычных меню 11 станций — как в NeoForge,
  см. [документ](../../docs/client-only-preview.md).
- **Клиент без мода** на сервере с модом входит как обычно и получает ванильные окна.

Экран настроек с поиском и вкладками встроен в мод, Cloth Config не нужен. Необязательно:
**JEI 15** (полевой справочник у станций; JER и JEP — через категории JEI), **Inventory Particles 3.2 /
Inventory Interactions 2.2** (эффекты инвентаря в панели сцены). Ни одна из этих зависимостей не обязательна
и не входит в JAR.

Профили раскладок станций совместимы с NeoForge-версией: файлы `config/cinematic-table-layouts.json`,
`cinematic-furnace-layouts.json`, `cinematic-surface-layouts.json`, `cinematic-spatial-layouts.json` можно
копировать между версиями (строка сборщика в последнем файле сохраняется как есть). Общие настройки —
`config/cinematic-client.toml`.

## Отличия от NeoForge 1.21.1 (осознанные)

- **Нет сборщика (Crafter)**: в Minecraft 1.20.1 этого блока нет. Новый блок мод не добавляет и чужой не подменяет;
  сцена сборщика, его акты Showcase и тексты исключены из этой версии.
- **Экран настроек** — собственный (поиск, вкладки и прокручиваемый список ванильных виджетов): в Forge 1.20.1
  нет встроенного экрана конфигурации. Тот же экран, что в NeoForge, без Cloth Config.
- **Совместимость с Punchy** не переносилась: Punchy для Forge 1.20.1 нет. Проход рук первого лица скрывается
  отменяемой инъекцией в начало `ItemInHandRenderer.renderHandsWithItems` и событием Forge `RenderHandEvent`
  (Forge 1.20.1 не поставляет MixinExtras, обёртка метода недоступна).
- **Мышь во время сцены** держит маленький миксин `MouseHandlerMixin` (в NeoForge для этого есть событие
  `CalculatePlayerTurnEvent`, в Forge 1.20.1 — нет).
- **Настройки пишутся через `Settings.set`.** Forge 1.20.1 сохраняет файл при каждом `set()` и перечитывает его из
  отдельного потока; если перечитывание попадает между двумя быстрыми записями («Готово» на экране настроек пишет много
  значений подряд), в памяти оказывается старое значение, а наполовину прочитанный файл Forge «исправляет»
  значениями по умолчанию. Значения, записанные в последние 3 секунды, после такой перезагрузки записываются снова.
- **Крен камеры** задаёт событие Forge `ViewportEvent.ComputeCameraAngles` (в 1.20.1 у камеры нет крена);
  `CameraMixin` поворачивает вместе с ним собственные векторы камеры, по которым смотрят частицы и билборды.
- **Вспышка у зачарования для зрителей**: в Forge 1.20.1 нет события зачарования предмета; сервер узнаёт о нём по
  росту ванильной статистики «Предметов зачаровано» у игрока у стола (раз в тик).
- **Топливо печей в клиентском режиме**: в Forge 1.20.1 клиент знает топливо (оно задаётся кодом, а не
  data map), поэтому Shift+клик в печь на ванильном сервере предсказывается так же, как у остальных меню.
- **Наковальня**: можно ли ковать, решает слот результата самого меню (`mayPickup`), как в его окне, а не своя
  формула «цена > 0 и хватает уровней». Для ванили это то же самое; с Easy Anvils (бесплатное переименование,
  цена 0) в NeoForge 0.18.11 сцена отказывалась ковать.
- Книги, знамёна, зелья, карты, пластинки и отделка брони — **NBT 1.20.1** вместо компонентов; рецепты — по
  контейнеру 3×3 и `Recipe.getId()`; эффекты маяка — `MobEffect`, чары — объекты `Enchantment`.

## Сборка

Нужен JDK 17 (Gradle сам подбирает toolchain 17; для запуска Gradle подходит JDK 21). Wrapper — Gradle 9.2.1,
ModDevGradle Legacy 2.0.148, Forge 47.4.10, Parchment 2023.09.03.

```bash
export JAVA_HOME="путь к JDK 21 или 17"
./gradlew build
```

Игровой JAR (SRG-имена, refmap миксинов, `MixinConfigs` в манифесте): `build/libs/Cinematic Interaction-Forge-1.20.1-0.18.11.jar`.
Исходники Minecraft/Forge 1.20.1 с именами Parchment для сверки API — `refs/src`, ресурсы ванильного клиента — `refs/client`.

## Проверка

- `bash tools/showcase.sh` — автотест в игре (те же акты и имена кадров, что в NeoForge, без актов сборщика),
  `ONLY=true FROM=k bash tools/showcase.sh` — один акт; `EXTRA="-PwithJei" ...` — с тестовыми модами.
  Акт `cr` — рецепты из датапака мира (shaped с NBT в результате, своя плавка).
- Тестовые моды по флагам Gradle (`-PwithJei`, `-PwithJeiFull`, `-PwithInventoryEffects`,
  `-PwithInventoryParticles`, `-PwithShaders`, `-PwithAmendments`, `-PwithEasyMods`, `-PwithProfile`) лежат в
  `test-mods/` (SHA-256 — `test-mods/SHA256SUMS.txt`) и подключаются только к запускам из Gradle.
- `python tools/join_test.py` — выделенный сервер Forge с модом (`-PjoinTest`, 127.0.0.1:25589), ServerSmoke,
  сохранение мира, перезапуск и повторный вход.
- `python tools/client_only_test.py` — клиентский режим на чистом ванильном сервере 1.20.1 (127.0.0.1:25586);
  `--server forge` — то же на сервере Forge **без** Cinematic Interactions (`./gradlew runPlainServer -PjoinTest`).
- `python tools/prod_client.py --forge 47.4.20 --dir run-prod --mods build/libs/*.jar --jvm=-Dcinematic.showcase=true`
  — настоящий (не dev) клиент из установок Modrinth (47.1.106, 47.3.12, 47.4.0, 47.4.20), ничего не скачивая;
  `--client prod` у тестовых скриптов запускает его вместо dev-клиента. Собранный JAR проверяйте только так:
  dev-запуски не видят ошибок переобфускации (refmap миксинов) и ранних `return` в настоящем байткоде игры.

Во всех каталогах запуска `options.txt` содержит `soundCategory_master:0.0`. Не пересобирайте проект, пока его
тестовый клиент работает.
