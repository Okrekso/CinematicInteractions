# Cinematic Interactions — Fabric 26.3

Отдельный порт Cinematic Interactions **0.18.28** на Minecraft **26.3**. Старые порты 1.21–1.21.11 собираются
соседним проектом и не используют эти исходники.

Перенесены редакторы всех станций, режим разработчика, три локальных профиля каждой станции, выбор профилей
в настройках и индикаторы приготовления еды у костра. Анимация кровати не входит в мод.

**Статус:** в 0.18.28 перенесены изменения актуальной Fabric 26.2: режимы рук и быстрого возврата, исправления верстака, зачарования и взаимодействий, JEI, выбор конфликтующих рецептов через Polymorph+. Для печей сохранён исправленный рендер свечения под шейдерами. Ниже приведена история прежних проверок. Порт 0.18.0 проверен в игре, с Iris/Complementary и на отдельном сервере;
исправление Punchy в 0.18.1 проверено в обычном и шейдерном клиентах, а также без Punchy.
В 0.18.2 добавлена необязательная совместимость с Inventory Particles и Inventory Interactions
для панели инвентаря и предметов станций. Устройство и команды проверки —
в [документе совместимости](../../docs/inventory-effects-compat.md).
В 0.18.6 исправлена передача рецептов, из-за которой некоторые сторонние динамические рецепты
отключали игрока при входе в мир. У сидящего у костра игрока теперь восстанавливается потерянный
таймер еды, а при остановке тика костра приготовление продолжает ванильный механизм.
Результаты и границы проверки — в [TESTING.md](TESTING.md).

Добавлен пробный **клиентский режим** по образцу NeoForge 1.21.1. В разделе «Сетевая игра» настроек мода
его можно включить только из главного меню; выбор применяется при следующем подключении. На сервере без
Cinematic Interactions поддерживаемые станции открывают локальные сцены поверх обычных меню Minecraft.
Предметы и рецепты обрабатывает сам сервер, игрок остаётся на месте, а камера не уходит дальше 0,35 блока
от глаз и не проходит сквозь стены. Когда рабочую область не видно или до неё не дотянуться, остаётся
обычное окно. Если мод есть и на сервере, действует полный прежний режим независимо от переключателя.
Справочник у верстака берёт доступные рецепты из обычной книги Minecraft, поэтому его подсказки работают
без расширенного пакета рецептов мода.

Клиентский режим охватывает верстак, все три печи, стол зачарования, наковальню, точило, кузнечный стол,
камнерез, ткацкий станок и стол картографа. Прочие станции на сервере без мода остаются ванильными.
Подробные ограничения описаны в [документе NeoForge](../../docs/client-only-preview.md): предметы на верстаке
видны лишь работающему игроку до закрытия меню, а общие эффекты и позы других игроков требуют серверной части.

## Установка

Готовый файл: [Cinematic Interaction-Fabric-26.3-0.18.28.jar](https://github.com/dcvke/CinematicInteractions/releases).
Прежние JAR сохранены; в папку `mods` устанавливайте только одну версию Cinematic Interactions.
Нужны Minecraft **26.3**, Java **25**, Fabric Loader **0.19.5+** и Fabric API **0.163.0+26.3**.
Для полного режима один и тот же JAR устанавливается в `mods` клиента и сервера. Пробный клиентский режим
работает с этим JAR только на клиенте при включённом переключателе.
Для доступа к настройкам через список модов установите Mod Menu; Cloth Config добавляет экран с вкладками,
а при его отсутствии используется встроенный экран.

Профили из NeoForge можно скопировать в `config`: `cinematic-table-layouts.json`,
`cinematic-furnace-layouts.json`, `cinematic-surface-layouts.json`, `cinematic-spatial-layouts.json`.
Общие настройки хранятся в `cinematic-client.json`, автоматического импорта TOML нет.

## Сборка

Нужен **JDK 25**. Используйте wrapper из этой папки: Gradle 9.6.0, Fabric Loom 1.17.21.

```powershell
$env:JAVA_HOME = 'путь к JDK 25'
.\gradlew.bat build
```

Игровой JAR: `build/libs/Cinematic Interaction-Fabric-26.3-0.18.28.jar`.
Зависимости: Fabric Loader **0.19.5+**, Fabric API **0.163.0+26.3**. Для полного режима один и тот же JAR нужен на клиенте и сервере; пробный клиентский режим работает без серверного мода.
Cloth Config и Mod Menu необязательны; без Cloth Config доступен встроенный экран настроек.

## Проверка

```powershell
.\gradlew.bat runShowcase -PwithSettings
.\gradlew.bat runShowcase -PwithSettings -Pfrom=a -Ponly=true
.\gradlew.bat runShowcase -PwithSettings -PwithShaders -Pfrom=a -PeditorBatch=true
.\gradlew.bat runServer
.\gradlew.bat runClientOnlySmoke
```

Showcase создаёт отдельный мир в `run/showcase` или `run/showcase-iris`. Снимки сохраняются в `screenshots`,
проверки и замеры плавности — в журнал. Для шейдерного прогона нужен включённый пакет в
`run/showcase-iris/shaderpacks` и `config/iris.properties`. Iris 1.11.7 и Sodium 0.9.3-alpha.1 подключаются только
при `-PwithShaders`; библиотеки Iris извлекаются автоматически для запуска из среды разработки.

Не пересобирайте проект, пока его игровой клиент запущен.

`runClientOnlySmoke` подключается к отдельному чистому серверу 26.3 по `127.0.0.1:25587`. Для проверки
нужны верстак `(0,64,1)`, печь с фасадом на север `(1,64,1)`, наковальня с длинной стороной на восток
`(-1,64,0)`, стол зачарования `(1,64,-1)` и бревно дуба в первом слоте игрока. Тест временно включает
переключатель в памяти, проверяет крафт, четыре сцены, закрытие меню и отсутствие движения игрока;
итог пишет как `[ClientOnlySmoke] PASS`.
В обычном запуске тестовый код неактивен.

## Особенности переноса

- Игра использует Java 25 и открытые имена классов, поэтому слой mappings не нужен.
- Геометрия сцены записывается во время extraction и передаётся в обычную очередь features Minecraft.
  Прозрачные предметы сохраняют индивидуальную альфу, оттенки материалов и свечение.
- Камера подключена перед расчётом её матриц; время сцены обновляется после игровых тиков и до обновления камеры.
- Интерфейсы используют `GuiGraphicsExtractor`; кнопки SDL преобразуются в прежние логические номера только
  на границе ввода. Серверные номера кнопок и слотов не меняются.
- Страницы книги рисуются в собственные текстуры через отдельную очередь features и render pass.
- Координаты редакторов, предметов, рук, подсказок рецепта и кликов используют общую геометрию из NeoForge.
- JSON-профили имеют те же имена и форматы, что и NeoForge. Общие настройки Fabric хранятся в
  `config/cinematic-client.json`; TOML автоматически не импортируется.

Текстуры, переводы и модель молотка берутся из `../../src/main/resources`. Определение модели предмета молотка
использует совместимый ресурс из `../src/1.21.5/resources`. Исходники Minecraft и Fabric API для проверки API
распакованы локально в `refs/` и не входят в JAR.
